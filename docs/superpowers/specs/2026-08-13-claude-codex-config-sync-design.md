# Claude ↔ Codex config sync

**Date:** 2026-08-13
**Status:** Approved, ready for implementation plan

## Problem

Instructions, skills, and hooks are maintained separately for Claude Code
(`~/.claude`) and Codex (`~/.codex`). They have drifted. The drift is two
different problems wearing one coat, and conflating them is why previous
hand-syncing failed.

**Accidental drift — pure loss:**

- `# Secrets` exists only in `CLAUDE.md`. Codex has no instruction about
  `~/dev/8x_Internship/Keys/` at all.
- `~/.codex/hooks/block-secret-reads.sh` is the 2026-07-29 version at 2.2 KB;
  `~/.claude/hooks/block-secret-reads.sh` is 4.2 KB. Codex runs half a guard.
- `marcel-detector.sh` is wired on Claude only.
- 17 skills are installed for Claude and missing for Codex.

**Intentional divergence — copying it over would break Codex:**

- Each host must be told the *other* model is the read-only reviewer.
- Skill names differ: `/review` on Claude, `gstack-review` on Codex.
- `ultracode` (agent fleets) exists only on Claude; Codex's equivalent lever is
  reasoning effort.

A naive symlink erases the second category and tells Codex to invoke commands
that do not exist on its host.

### Severity note

Codex's `config.toml` has no deny-rule mechanism — `rules/default.rules`
contains allow-only `prefix_rule` entries. Claude backs its hook with 12
`permissions.deny` rules; Codex has nothing behind it. The stale 2.2 KB script
is Codex's *only* protection for the Keys directory. Replacing it is the
highest-value single change in this spec.

## Non-goals

- Deduplicating the 2.2 GB of divergent skill trees at `~/.claude/skills/gstack`
  and `~/.agents/skills/gstack`. Real, but separate risk.
- Fixing the `.Codex` vs `.codex` case-typo in `~/.codex/rules/default.rules`.
- Translating `settings.json` into `config.toml`. Two vendor schemas that change
  independently; owning a translator between them is a maintenance trap.

## Architecture

One canonical source in the versioned repo. Both hosts' files are generated
from it.

```
~/.claude/sync/
  core.md                  shared instruction template
  overlay.claude.md        Claude-only sections + variable bindings
  overlay.codex.md         Codex-only sections + variable bindings
  hooks/
    block-secret-reads.sh  the single real copy (current 4.2 KB)
    marcel-detector.sh     the single real copy
  sync.sh                  apply | --check
```

`~/.claude/sync/` is chosen over a neutral `~/.agents/` because `~/.claude` is
the only one of these directories that is a git repo with a remote. The source
of truth must be versioned and pushed.

### Template variables

The routing prose is dense with host-specific command names. Duplicating it into
both overlays would recreate the drift one layer down, so `core.md` is a
template and `sync.sh` substitutes. The prose stays single-sourced; each host
still gets its exact names.

| Variable | Claude | Codex |
|---|---|---|
| `{{SELF}}` | Claude Code | Codex |
| `{{OTHER}}` | Codex | Claude |
| `{{REVIEW}}` | `/review` | `gstack-review` |
| `{{SPEC}}` | `/spec` | `gstack-spec` |
| `{{AUTOPLAN}}` | `/autoplan` | `gstack-autoplan` |
| `{{SHIP}}` | `/ship` | `gstack-ship` |
| `{{CHALLENGE}}` | `/codex challenge` | `gstack-claude challenge` |
| `{{BRAINSTORM}}` | `superpowers:brainstorming` | `brainstorming` |

Substitution is literal string replacement. `sync.sh` fails if any `{{...}}`
token survives into the output — an unbound variable is a bug, not a default.

### Section allocation

**`core.md` (shared):** `# Secrets`, `# Skills`, `# Git commits`,
`# Skill routing`, and a short shared `# Effort` principle.

`# Secrets` is generalised: it currently names `~/.claude/settings.json` and
`~/.claude/hooks/`, which is false on the Codex host. Rewritten to reference the
host's own deny rules and the shared guard script.

**`overlay.claude.md`:** `# Ultracode`, `# Model allocation`.

**`overlay.codex.md`:** `# Heavy work: turn the effort up`.

Correction to an earlier claim during design: `# Model allocation` is *not*
accidental drift. Its content is entirely about `Agent` dispatches, workflow
fan-out, and per-stage `effort` — mechanisms Codex does not have. It is
correctly Claude-only. Only the general principle (match cost to task
difficulty) belongs in `core.md`.

### Outputs

| Path | Action |
|---|---|
| `~/.claude/CLAUDE.md` | generated: core + claude overlay |
| `~/.codex/AGENTS.md` | generated: core + codex overlay |
| `~/.claude/AGENTS.md` | retired to `~/.claude/backups/` |
| `~/AGENTS.md` | retired to `~/.claude/backups/` |

Generated files carry a first-line header:

```
<!-- GENERATED by ~/.claude/sync/sync.sh — edit sync/core.md or sync/overlay.*.md, not this file -->
```

Both stale copies are **moved, not deleted**. `~/.claude/AGENTS.md` is retired
because nothing reads it — evidence: this session's system prompt loaded only
`CLAUDE.md`. `~/AGENTS.md` is retired because Codex already loads
`~/.codex/AGENTS.md` globally, so a near-copy at `~` double-loads the same
instructions into every Codex session started under the home directory.

### Hooks

The two `.sh` scripts move to `sync/hooks/` and become the only real copies.
`~/.claude/hooks/*` and `~/.codex/hooks/*` become symlinks to them. This is what
closes the security gap.

Claude's `settings.json` `hooks.PreToolUse` block and Codex's `hooks.json`
`hooks.PreToolUse` block are already byte-identical apart from the script path,
so this needs no schema translation.

One gap is fixed by hand as part of implementation: Codex's `hooks.json` has no
`UserPromptSubmit` entry, so marcel-detector never runs there.

### Settings: audit, never rewrite

`sync.sh` owns the files it generates and never edits `settings.json`,
`config.toml`, or `hooks.json`. It asserts and reports:

- Both hosts' hook scripts resolve to `sync/hooks/`.
- `settings.json` still carries the Keys `permissions.deny` rules.
- `hooks.json` wires both scripts.

A failed assertion prints the gap and exits nonzero. Fixes are manual.

### Skills

Symlink 17 skills into `~/.codex/skills/` pointing at `~/.claude/skills/`.
All 17 targets are confirmed to exist:

```
_gstack-command  connect-chrome  docx  emil-design-eng  expo-native-ui
expo-router  expo-web-to-native  find-skills  gemini-media
higgsfield-generate  higgsfield-soul-id  higgsfield-video-explainer
humanizer  impeccable  pptx  react-native-best-practices  xlsx
```

Link target is `~/.claude/skills/`, not `~/.agents/skills/`. The two trees have
diverged and the `~/.agents` copy is stale — `~/.agents/skills/review/SKILL.md`
is empty where Claude's has valid frontmatter. Codex's existing `gstack-*`
symlinks already point into the `~/.claude` tree.

**Permanent exclusion:** `codex` (Claude-only) and `gstack-claude` (Codex-only)
are the outside-voice skill on each host. They are correctly asymmetric and are
excluded from the audit so it does not flag them on every run.

`--check` reports any *new* asymmetry, which is what catches a future gstack
install landing on one host only.

### Repo bookkeeping

`~/.claude/.gitignore` is an allowlist — it ignores everything, then re-includes
named paths. Two new entries are required or the work cannot be committed:

```
!sync/**
!docs/**
```

`~/.codex` is not a git repo. Its generated files are therefore unversioned;
they are reproducible from `sync/` in the `~/.claude` repo, which is the point
of putting canonical source there. Converting `~/.codex` into a repo is out of
scope.

## Triggers

- **SessionStart** → `sync.sh --check`. Measured at 19 ms including shell
  startup. Catches drift introduced outside Claude Code — Codex editing its own
  file, or a gstack upgrade.
- **PostToolUse**, matched to the synced paths → warns immediately when a synced
  file is edited. Unrelated edits never fire it; the matcher filters first.

Neither trigger rewrites anything. Regeneration happens only when `/sync-agents`
is run explicitly. This is deliberate: auto-regeneration would silently revert a
direct edit to `CLAUDE.md`, and silent reversion of a security instruction is a
worse failure than one stale session.

## Failure modes

| Failure | Behaviour |
|---|---|
| Unbound `{{VAR}}` in output | `sync.sh` aborts, writes nothing |
| `~/.codex` absent | Claude outputs still generated; Codex steps skipped with a notice |
| Skill link target missing | Link skipped, reported; not created dangling |
| Settings assertion fails | Reported, exit nonzero, no file edited |
| Direct edit to a generated file | Next check warns that it diverges from core |

## Verification

1. `sync.sh --check` exits 0 on a clean tree.
2. Generated `CLAUDE.md` contains `# Ultracode`; generated `AGENTS.md` does not.
3. Generated `AGENTS.md` contains `gstack-review`; neither output contains a
   surviving `{{` token.
4. `~/.codex/hooks/block-secret-reads.sh` resolves to `sync/hooks/` and is 4.2 KB.
5. Skill count parity holds after excluding the reciprocal pair.
6. Corrupt one output by hand; `--check` reports it and exits nonzero.
7. Both hosts start a session cleanly with the generated files in place.

## Rollback

Everything replaced is copied to `~/.claude/backups/` first. Rollback is
restoring those files and removing `sync/`. The `~/.claude` side is additionally
recoverable from git.
